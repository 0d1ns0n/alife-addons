# Разработка

## Как устроен репозиторий

```
mods/            готовые к установке папки модов (копия из игры)
docs/            описание модов, как делиться, эта страница
tools/           скрипты и тесты
CHANGELOG.md     журнал обновлений
```

Рабочие копии модов лежат в игре: `%UserProfile%\Zomboid\mods`. Я правлю их там, проверяю в игре, а в репозиторий переношу скриптом.

## Обновление репозитория

```
python tools/sync_from_game.py        # скопировать моды из игры в mods
python tools/tests/run_tests.py       # тесты
git add -A
git commit -m "ALifeCamp 0.6: ..."
git push
```

Что нужно сделать при каждом обновлении:

1. Повысить `modversion` в `mods/<Мод>/42/mod.info` (правится в игре, потом sync).
2. Записать изменения в `CHANGELOG.md`: новое сверху, с отметкой «тесты» или «в игре».
3. Если мод сильно изменился, поправить страницу в `docs`.
4. Перед выпуском `python tools/tests/run_tests.py --all` (с длинным тестом полного цикла лагеря, около 4 минут).

## Устройство ALifeCamp

Общий код лежит в `shared/ALifeCamp`, серверная работа в `server/ALifeCamp/CampWork.lua`, интерфейс в `client/ALifeCamp`.

| Файл | Роль |
|---|---|
| `CampConfig`, `CampGeo`, `CampStore`, `CampText` | настройки, геометрия, хранилище (ModData), тексты |
| `CampWorld`, `CampStock`, `CampLand`, `CampClear` | работа с клетками, склад, классификация земли, расчистка |
| `CampPlace`, `CampEntities`, `CampBlueprints`, `CampBuild` | размещение объектов, ванильные сущности, чертежи, стройка по стадиям |
| `CampPlan`, `CampGates`, `CampPosts`, `CampDistricts` | генерация плана, ворота, блок-посты и общие здания, районы |
| `CampSettlers`, `CampSkills`, `CampRecycle`, `CampStats` | люди, навыки, переработка, статистика и уровни |
| `CampMotor` | военная техника, парковка, ремонт |
| `CampAdopt`, `CampSalvage`, `CampFortify`, `CampFitout` | обживание домов |
| `CampExpand`, `CampSite` | расширение, площадки стройки |
| `CampWork` (server) | минутный цикл: приход людей, еда, добыча, расчистка, стройка, огороды, налёты, приказы |

Идея: объекты, поставленные лагерем, помечаются в `modData.ALC` (`kind`, `camp`, `project`, `slot`), расчистка такие объекты не трогает.

## Правила кода

* Без комментариев в коде: код должен читаться сам.
* В Lua-файлах нет русских строк. Весь текст идёт через `getText("UI_ALC_...")` (`ALifeCamp.T(key, ...)`), переводы лежат в `Translate/RU/UI.json` (в Build 42 переводы только в JSON).
* Lua в игре читается только при запуске: любая правка требует перезапуска игры.
* Kahlua (Lua игры) не умеет: `math.random` (нужен `ZombRand`), `...` во вложенных функциях, `goto`; остаток от деления отрицательных чисел отрицательный. Любой вызов движка, который может упасть, оборачивается в `pcall`.
* Клетки вне загруженной зоны возвращают `nil`: перед работой всегда проверять `World.square(x, y, z) ~= nil`.
* Нет жёстких потолков: размер лагеря и число людей не ограничены, но каждый шаг ограничен бюджетом, чтобы игра не подвисала.
* Нельзя называть новую функцию так же, как существующую таблицу или функцию модуля. Один раз такое сломало склад материалов.

## Тесты

Тесты запускают настоящие файлы мода внутри Lua (пакет `lupa`) на поддельном движке (`tools/tests/camp_mock.lua`).

```
pip install lupa
python tools/tests/run_tests.py             # быстрые тесты
python tools/tests/run_tests.py --all       # и длинный полный цикл
python tools/tests/run_tests.py camp_test8  # один тест
```

Проверка на модели не ловит ошибки движка: настоящую проверку делает игра. Поэтому в `console.txt` каждые 30 игровых минут пишется строка состояния лагеря, а в журнале обновлений у каждой возможности стоит отметка «тесты» или «в игре».
